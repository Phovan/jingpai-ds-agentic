# jingpai-ds-agentic

劲牌企业大脑交互 Demo。React + TypeScript + Vite 应用工程，不是单文件 HTML。最新 28 个 Story 的可点击主路径及模拟边界见 [Story 覆盖 V0.1.3](docs/story-coverage-v0.1.3.md)。

## 运行

需要 Node.js 22.12+ 或 24 LTS。

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:5173/ 。共11个演示角色，无需密码。新增项目成员、系统负责人、测试、运维工作台；系统管理员进入知识接入工作台。左下角「设置 → 切换演示身份」，切换不清空业务状态。新增 Story 从工作台下方的场景入口进入。

```bash
npm test
npm run build
npm run preview
```

预览服务默认仅绑定本机，不自动部署、不对外公开。数据保存在当前浏览器的 localStorage；会话身份保存在 sessionStorage。不同浏览器或设备不共享数据，同源标签页通过版本校验和 Web Locks 防止并发覆盖。刷新可继续，关闭页面后模拟执行暂停，重新打开继续。

## 建议演示顺序

| 步骤 | 登录角色 | 操作 | 看什么变化 |
| --- | --- | --- | --- |
| 1 | 管理层 | 晴雨表 → 查看事项 → 比较方案 A/B → 填依据、确认影响 → 批准 | 保存决定，不把预测或目标直接变绿 |
| 2 | 项目经理 | 项目与目标 → 确认资源与交付安排 | 同一 REQ-024 的预测更新，EOS 收到执行计划 |
| 3 | 研发 | 系统与版本 → 可勾选一次派发失败 → 启动 / 重试 | 同一 TASK-024 被受理；回执依次出现 |
| 4 | 研发 | 等待约 7 秒，遇现实验证阻塞 → 补充环境回执 | 缺少身份权限证据时不假绿；重试保留失败记录 |
| 5 | 项目经理 | 系统与版本 → 确认预览发布 | 仅模拟 preview；仍待业务验证，目标还是 3.5h |
| 6 | 业务Owner | 需求 → 验证业务结果，填写样本说明与实测值 | ≤2h 才能通过；需求关闭，目标实际值回写；不达标可退回原需求 |
| 7 | PMO | 经验库核实候选；报告生成周报 | 根据当时事实生成快照，不代替员工确认 |
| 8 | 四个责任角色 | 项目经理、Owner、产品、研发分别确认本人事项 | 回复不足时 PMO 不能提交；未回复不等于同意 |
| 9 | PMO → 管理层 | PMO 核对，管理层确认 | 固化报告；下一轮会归档旧快照 |

方案 B 需要业务 Owner 先确认延期的业务影响，再由项目经理回写日期；不能由管理层批准直接跳过业务确认。

另一条可交互链：Owner 新建需求 → 产品起草验收条件 → Owner 确认基线 → 项目经理排期。新增需求进入待开发队列。首版工程执行、发布与结果验证闭环聚焦 REQ-024，不宣称所有新增需求都能自动生成实现。

## V0.1.1 对话与工作台

- 左侧：劲牌企业大脑、新对话、工作台、最近对话及自定义分组；底部从上到下为反馈意见、设置。
- 中间：每日简报、与角色相关的关注事项、对话输入。历史对话可继续、重命名和移动分组；分组可新建、重命名、折叠。
- 右侧产出与输入材料默认收起。可显式生成当前角色的追踪摘要、粘贴输入文本；均为本地演示，材料不发送给真实模型。
- 工作台支持研发、产品、营销、服务、采购、运营、未分类；可组合搜索、对象类型和差距筛选，分页每页 6 个对象。领域示例不是客户事实，也不代表全量客户项目。
- 对象清单展示目标、当前值、差距和下一步。对象与业务工具均可关注，形成角色自己的快捷入口。业务页面从工作台进入，不再常驻左侧菜单。
- 个人对话、分组、关注、材料、反馈按角色在本机保存；不支持个人空间多标签并发合并。业务重置不会删除个人空间，历史问答和产出仍是旧快照。

## 已实现的交互

- 六个演示身份、统一对话入口、角色相关目标与工作台、领域层权限校验。
- 管理层目标 GAP / 晴雨表；PMO 的报告核对入口；项目经理的资源与承诺；Owner 生命周期；产品验收基线；研发执行回执。
- 上下文大脑问答：依据当前共享状态回答目标、证据、责任、需求、报告。查询只读，涉及变更须进入明确动作面板。
- 两类 Agent 无登录入口，以行动发起者与执行者出现；低风险回执自动推进，关键决定与业务验证等待人。
- 派发失败、幂等重试、停止、验证阻塞、补证、验收退回、版本冲突、重复提交拦截。
- 报告分角色确认、补充证据、PMO 核对、管理确认、历史快照归档。
- 对象搜索、项目筛选、需求筛选、通知、经验核实、本地持久化、导出 JSON 快照及二次确认重置。
- 桌面布局与移动端导航、原生模态焦点约束、键盘焦点、减少动态效果。

## 工程边界

本轮构建与 36 项测试通过，浏览器验证范围见 [验证记录](docs/verification.md)。Figma 当前为上一版的六角色交互意图原型；本轮以实际应用及本地设计规格为准，未继续此前待确认的页面上传。

这是交互与业务状态的演示系统，不是生产系统：

- 演示身份可以自由切换；前端权限用于展示流程，不能替代服务端认证、组织级数据隔离与授权。
- 大脑使用显式规则；EOS 的实现、审核、验证、预览发布都是确定性模拟，不运行真实代码、不调用模型 API。
- EnlightAI 仅打开用户指定官网入口，未接入任务 API、深链、回调或登录态。页面不声称真实同步。
- 其他组合项目为只读分类示例；运行事件、供应商全流程、正式月季报、生产发布与真实收益归因不在本版实现范围。
- 独立审核由单独命名的模拟 Reviewer 步骤体现，尚无真实测试人员 / 运维人员账号。项目经理仅确认演示预览发布，不能代表真实生产授权。
- localStorage 中不要放客户敏感信息。无后台服务、多人远程共享、上传附件或真实 BI / 财务 / 人事接入。
- 整体版本号是保守冲突检查：即使不相关对象变化也可能要求重新确认。生产版应改为对象级版本与服务端事务。
- 导出用于保留和检查演示快照；本版不提供导入按钮。

## 代码结构

`src/domain/model.ts` 是纯业务状态机和权限入口；`store.ts` 处理持久化、并发与 Agent 时钟；`src/pages/` 是各工作面；`src/components/` 是公用对话框、大脑问答及基础组件。未来接真实模型或 EnlightAI 时，应实现适配器并保留状态机守卫，不能让模型回答直接覆盖对象状态。

源文件修改后不自动同步知识库。仅在用户明确执行同步命令时操作。
