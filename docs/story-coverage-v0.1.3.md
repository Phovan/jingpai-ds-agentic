# PMO / EOS Story 演示覆盖 V0.1.3

更新：2026-09-18。依据 101、102 UserStory V0.1.3 与 000 通识原则 V0.1.1。

28 个 Story 均有对应的可操作主路径。这里的“覆盖”指本地 Demo 的角色、对象、交接、门禁和回执，不代表生产实现或所有边界分支均已验收。保留现有三栏 UI，不重新设计主题。

## 入口与角色

工作台下方的场景入口：战略与项目、工作承诺、风险闭环、系统健康、版本与审核、周期报告、经验复用、资料核实。原需求入口继续使用同一需求对象，不另起一套需求数据。场景列表可搜索、筛选，详情可追问和关注。

设置 → 切换演示身份。共 11 个角色：管理层、PMO、项目经理、业务Owner、产品经理、研发、系统管理员、项目成员、系统负责人、测试、运维。PMO Agents / EOS Agents 不登录。

## 最快演示三条链

1. PMO 新建项目 → Owner、系统负责人、PMO分别确认 → 管理层批准 → PM分派工作 → 成员提交 → PM验收 → Owner验证结果 → 系统负责人移交。
2. PM编排版本 → 研发、测试、运维、系统负责人分别确认就绪 → 研发提交实现 → 测试独立审核 → 系统负责人和Owner确认门禁 → 运维发布 → Owner验证。任何一次退回保留记录。
3. PMO或系统负责人生成周期报告 → 列出的责任角色逐一确认 → 两位专业负责人核对 → 管理层确认并分派后续行动 → 下期报告查看落实。

## 验证与边界

- 73 项自动测试通过，构建通过。新增测试覆盖立项、承诺、风险、系统证据、版本门禁、变更、独立审核、发布/回退、报告、经验和资料范围。
- 桌面实际点击验证：PMO草拟项目并保存详情；PM编排版本并打开需求/Issue关联。其余跨角色链通过状态测试，未逐个重复完整浏览器回归，未做多端巡检。
- 接口、AI推理、代码生成、自动测试、独立审核工具、生产发布与监控均未接真实服务。人工录入模拟证据；不能把演示通过当成真实验证通过。
- 项目、战略、人员角色、日期、指标均为演示数据；不引用 001 占位战略。原存档按需补充新对象，不清空已有演示数据。
- 版本按所选需求整体覆盖验收，未实现复杂并行部分发布；需求主路径优先演示研发型诉求，咨询/配置的自动处理工具仍属接入边界。
- 资料支持本地选定文本、来源版本、可见范围和核实；连接器定时任务仍为模拟计划，不会执行真实同步命令。角色控制为Demo操作边界，不是生产认证或数据库级隔离。
- 旧入口保留兼容。需求编入新版版本流程后，旧工程快捷命令被拦截，不能绕过独立审核和发布门禁。
