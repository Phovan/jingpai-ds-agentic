# 项目交付与会议演示增量

本轮沿用已确认的清单、详情、会话与右侧执行面板，不恢复旧场景菜单。所有新增记录为本地合成演示事实，不代表客户现状。

## 范围与交互

- 项目清单及摘要分开显示业务目标、交付阶段、交付完成度、参与方、风险类别；业务指标达标不等于交付完成。
- 重点案例：海外用户洞察（需求）、原料溯源（开发）、市场健康与渠道配额（测试）、评论区问题闭环（运维问题修复）。
- PMO 默认增加会议；项目相关会议可下钻议题、观点、结论、责任人及行动。
- 问题与行动：保留 AI 原建议，人工修订或退回；批准后才产生责任人待办；提交证据后由审核人验收或退回。
- 需求验收确认后，项目经理确认资源、日期和实施计划，形成 Issue 执行队列。研发从 Issue 发起 EOS。
- EOS 独立复审后增加人工关口；不通过必须填写理由，保留旧轮次和失败证据，生成新的修复轮次。未经批准不得进入验证。
- 测试项目展示多日缺陷快照、严重级别、责任人、复测和发布门禁；缺陷下降不自动批准发布。

## 保持边界

不扩展 PMO 业务线组合汇总；不实现真实测试、生产发布及业务验收全链路。保留现有“转测试”。不恢复测试登录角色。人工审核只在本地角色模拟权限内生效，无真实通知、代码执行或发布。

## 操作提示与可复现数据

- 管理层、PMO 可见全部目录。项目经理被分派到上述四个重点项目；研发除原有范围外可见海外案例。业务Owner仍只负责评论区项目。
- 行动责任人选择为“研发工程师 / 数字经营部项目经理”，分别绑定研发、项目经理演示身份。通过设置中的“切换演示身份”接续同一浏览器共享业务状态，私人会话仍按角色隔离。
- 首页即时信息会出现待审核、待验收、本人待办及 EOS 人工审核事项；阅读消息不改变任务状态。点关联名称进入详情操作。
- 评论区需求已预置批准计划，可直接演示 EOS；批次与海外需求从待确认开始。未经确认不能启动其 Issue。
- 人工退回示例：“缺少乱序写入的精确读回证据；请补反例，再提交独立复审。”重提后通过示例：“新候选证据完整，仅批准模拟验证，不授权生产发布。”
- 修复不会把业务 KPI 自动改绿；缺陷账本是 9/18 的合成测试快照，任务验收不会自动将静态缺陷、生产发布或业务验收写成完成。
- 新增合成数据：5 场会议、4 个分阶段风险、6 个质量 Issue、4 个行动建议、2 个需求及按批准计划生成的 Issue / Impl。原始 V0.3 文件不改写。
